01 · PAIR THIS COMPUTER

Enter the pairing code

On the model computer, the operator starts pairing and gives you an eleven-digit code. Enter it here. This computer then connects by itself.

Relay: ·

A code works once and for ten minutes. A wrong code is used up; ask for a new one. The relay only forwards encrypted data and never learns the code.

Direct connection with a client.toml file instead

Get a fresh client.toml from the operator of your model computer. Both ends need the matching pairing code, signaling service and explicit STUN settings.

The configuration stays on this computer, outside your project folder. Keep it out of Git, chat messages and screenshots. Old Docker paths are replaced with local paths. TURN and model administration are not enabled by this panel.

02 · CONNECTION

Connect and check

  1. After pairing by code this computer connects by itself, also when the application starts again. With a client.toml file, start the matching host on the other computer and click Connect.
  2. When the light turns green, click Test backend. A model list checks the full path through the encrypted tunnel.

A pairing by code uses the HTTPS relay and works wherever normal web access works. A direct connection from a client.toml needs permission for peer UDP traffic; there is no automatic fallback between the two.

Using OpenCode in Docker?

The Docker Desktop profile runs its own transport and limits project access to D:\OpenCode. This panel does not start or monitor that separate stack. Use its Windows launcher and browser at http://127.0.0.1:24244/. Do not start both clients with the same pairing code.

Connection troubleshooting
  • Still connecting: check that the host is running, both configs match, clocks are synchronized, and signaling/STUN and direct peer traffic are permitted.
  • Access refused by the relay: the relay token for this computer expired, was revoked or is limited to other addresses. Ask the operator, or pair again with a new code.
  • Code not accepted: a code works once. Ask for a new one and type it again.
  • Pair rejected: get matching fresh configuration files. Do not weaken authentication.
  • New code required: an established tunnel consumes its code. After a full disconnect or restart, create a fresh pair on both computers. Never delete consumed-code markers.
  • Connected, but backend test fails: check that a model is loaded and the backend exposes the required privacy profile. The control panel does not bypass that check.
  • Local port occupied: stop the other native client or use another loopback port in the configuration.
