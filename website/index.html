How it works

Your familiar applications. Your chosen AI.

A local API for your applications COMPATIBLE CLIENTS

OpenCode, chat interfaces and other compatible applications connect to a local OpenAI-compatible API. k-lani-link carries their requests to the AI backend on your chosen computer and streams its responses back.

Outgoing HTTPS from both computers SEPARATE NETWORKS

In HTTPS mode, both computers connect outward to the selected relay. It forwards encrypted requests in one direction and encrypted responses in the other. The model API does not need a public incoming port.

Encrypted between your endpoints END TO END

The relay carries ciphertext. The paired endpoints encrypt and decrypt the content; the intermediary forwards the encrypted payload rather than receiving readable prompts and answers.

Pair once, then work ONE-TIME CODE

Use a pairing code in the connection panel. Add its local API address, key and model to your application. You can change compatible applications without moving the model to the work computer.

Choose the connection mode HTTPS OR WEBRTC

HTTPS mode uses its selected relay. WebRTC is a separate option for networks that permit peer connections, with authenticated transport and additional content encryption. TURN is an explicit option for WebRTC; there is no automatic switch between the two modes.

Choose the agent's working files OPTIONAL ISOLATION

The film shows a Windows MXC profile limiting the agent's project and network access. Docker recipes are also documented. The connection software supplies the permitted model API route; choose the profile and tools for your setup.

Request and reply

Encrypted data goes in. The same encrypted data goes out.

  1. Your application sends a request to its local k-lani-link API.
  2. The client encrypts the request. The relay forwards that encrypted payload to the paired model computer.
  3. The model computer decrypts the request and passes it to the selected AI backend.
  4. The reply returns in the other direction: encrypted by the model-side endpoint, forwarded through the relay, then decrypted by the work-side endpoint.
  5. Compatible clients receive streamed text, reasoning and tool calls when the selected backend supports them.

The connection uses the HTTPS access each network permits. Data is processed on the model computer you choose.
